# Phase 5I — CI probes + verify:foundation (evidence)

*2026-05-31. Foundation sub-phase 5I. This sub-phase produces the Foundation
block's "What's memorable" artifact: `npm run verify:foundation`.*

## What was built

A DB-probe harness (extends the 5F Vitest + `pg` setup) that proves the
foundation's three load-bearing guarantees, plus an aggregator that renders them
as a one-page inspection sheet.

- **`tests/helpers/db.ts`** — added `actAs(client, {sub, tenant_id, role})` and
  `asSuperuser(client)`. `actAs` becomes the `authenticated` role and sets the
  `request.jwt.claims` GUC that `auth.jwt()` / `auth.uid()` / `jwt_tenant_id()` /
  `has_role()` read, so RLS applies exactly as for a real signed-in user — no
  real JWT signing needed.
- **`tests/helpers/seed.ts`** — `seedTenant()` inserts one row into every
  tenant-scoped table (31 tables, FK-ordered, as a single PL/pgSQL block), plus
  the tenant + owner auth user. Audit rows fall out of the 5F triggers.
- **`tests/foundation/rls-cross-tenant.test.ts`** — seeds two distinct tenants;
  signed in as A, asserts ZERO of tenant B's rows are visible in **every** table
  that carries a `tenant_id` (the list is discovered from `pg_class`, so a new
  table is covered automatically — and would fail if its RLS policy were
  forgotten). Includes partitioned parents (`stock_movements`, `audit_log`).
- **`tests/foundation/role-matrix.test.ts`** — puts on each role via the JWT
  claim and asserts the matrix: finance reads subscriptions+audit_log but cannot
  update products; planner updates reorder_recommendations+purchase_orders but
  cannot read subscriptions; viewer reads products but INSERT is rejected by RLS
  (savepoint-guarded so the aborted statement doesn't poison the tx); warehouse
  updates inventory_levels but not products; owner does both.
- **`tests/foundation/wired-for.test.ts`** — the 8 wired-for dry runs: multi-
  location (Wave 2), role dashboards (Wave 3), cycle-count close (Wave 4), Rutter
  + Cin7 mock adapters conforming to `SourceAdapter` (Waves 5/7, compile-time
  contract + capability gating), ROI deltas reconstructable from audit
  before/after jsonb (Wave 6), pricing status swap, tier retention widening.
- **`scripts/check-craft.mjs`** (`npm run check:craft`) — token-discipline +
  trust-hierarchy guard: no hex colors or font-family literals anywhere in `src/`
  except the token file; the three canonical render-path components exist. This
  is the trust-hierarchy lint guard deferred from 5G.
- **`scripts/verify-foundation.mjs`** (`npm run verify:foundation`) — runs the
  foundation suite + craft guard and prints the inspection sheet.
