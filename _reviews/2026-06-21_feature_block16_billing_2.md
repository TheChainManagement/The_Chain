## What can be done better

- The billing auth boundary is weaker than the bench gate. `BenchGate` verifies real tenant membership before using the service-role subscription read in [src/app/(app)/layout.tsx:35](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/(app)/layout.tsx:35) through [:_64](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/(app)/layout.tsx:64). The billing entrypoints do not. `authedTenant()` in [src/app/choose-plan/actions.ts:17](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/choose-plan/actions.ts:17) through [:_26](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/choose-plan/actions.ts:26) and `ChoosePlanInner()` in [src/app/choose-plan/page.tsx:42](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/choose-plan/page.tsx:42) through [:_52](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/choose-plan/page.tsx:42) trust the JWT claim alone, then call admin-backed subscription helpers. A stale token for a removed member can still hit checkout/portal paths for that tenant. That is not acceptable on billing.
- The service-role subscription helpers swallow failures. `loadSubscription`, `applyStripeSubscription`, `setBillingCustomer`, and `findTenantByCustomer` ignore Supabase `error` results entirely in [src/lib/billing/subscription.ts:22](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/billing/subscription.ts:22) through [:_82](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/billing/subscription.ts:82). That means webhook reconciliation can return `200` while the DB update failed, and the success page can redirect as if activation worked when nothing was persisted. Silent failure on billing state is bad engineering.
- Token discipline is drifting again. The new billing CSS hardcodes sizes and spacing all over the place, e.g. `font-size: 13px`, `padding: 12px 16px`, `width: 4px`, `height: 4px` in [src/app/choose-plan/choose-plan.module.css:28](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/choose-plan/choose-plan.module.css:28), [:_133](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/choose-plan/choose-plan.module.css:133), [:_181](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/choose-plan/choose-plan.module.css:181), and `padding: 8px 14px` in [src/app/(app)/settings/billing/billing.module.css:54](/Users/themoreapp/More%20Technologies/projects/the-chain/src/app/(app)/settings/billing/billing.module.css:54). The master prompt explicitly bans hardcoded spacing and motion values.
- The billing slice has no serious test surface. There should be direct tests for paywall behavior, stale-membership rejection, checkout session metadata, success-page tenant guard, webhook signature failure, webhook retry/idempotency, and DB-write failure behavior. Right now the repo is relying on one helper test and an evidence markdown file.
