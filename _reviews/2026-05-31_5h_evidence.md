# Phase 5H — App shell + auth-gated layouts (evidence)

*2026-05-31. Foundation sub-phase 5H. This is the sub-phase the Phase 5 MG
screenshot checkpoint lands on (PROCESS.md Phase 5 checkpoint 1).*

## What was built

Three route segments under `src/app/`, each with its own layout chrome — they
share tokens, never layout (MASTER_PROMPT: marketing/auth and app never share
chrome):

- **`(marketing)`** — public surface, no rails. `layout.tsx` (top bar + footer),
  `page.tsx` (condensed Mona Sans hero + lede + cobalt CTA + the PO-chain aside
  with the active link ignited). Replaces the old placeholder root page.
- **`(auth)`** — centered, no rails. `signin` + `signup` pages, a shared
  `AuthForm` client component (`useActionState` + `useFormStatus`), token-styled
  inputs with cobalt focus rings, CTA via `ActionButton`. `actions.ts`:
  `signIn` (Supabase `signInWithPassword`), `signUp` (Supabase `signUp` →
  `bootstrap_tenant` RPC → `refreshSession`), `signOut`.
- **`(app)`** — the **Working Bench**. `layout.tsx` is the **primary auth gate**:
  a server `getUser()` check in a Suspense-wrapped `BenchGate` that redirects
  unauthenticated requests to `/signin`. Bench chrome = 220px left rail + 1fr
  surface + 280px right rail (asymmetric), throughput hairline + today tick at
  the bench bottom, scroll-progress + signal-scan atmosphere. Routes: `today`
  (empty bench state) + `inventory`/`forecasts`/`suppliers`/`reorder`/`flow`/
  `settings` (BenchStub — route + rail wired, feature lands in a later wave).

New components: `bench/LeftRail` (client, active-nav highlight + sign-out),
`bench/RightRail`, `bench/BenchAtmosphere` (pure-CSS scroll-timeline + scan, no
JS), `bench/PageHeader`, `bench/BenchStub`, `brand/ChainGlyph`.

New migration: `20260531130000_signup_bootstrap.sql` — `bootstrap_tenant(text)`
SECURITY DEFINER RPC that atomically creates tenant + owner membership + trial
subscription + profile + first audit row for the calling user.

## Architecture notes

- **Cache Components.** The bench reads the session cookie (dynamic), so the
  auth gate sits inside `<Suspense>` per the cache-components rule. Build output:
  `(app)` routes are **◐ Partial Prerender** (static shell + streamed gate);
  `/`, `/signin`, `/signup`, `/gallery` are **○ static**. No `force-dynamic`.
- **Atmosphere is pure CSS** (`animation-timeline: scroll()` for the progress
  bar; keyframes for the scan) — no framer-motion dependency added, transform/
  opacity only, reduced-motion respected by the global reset.
- **Auth provider is Supabase** (decided Phase 2, wired 5C). The auto-suggested
  `auth` skill (Clerk/Auth.js/Auth0) was not applicable and was not invoked.

## Scope boundary (stated)

Sign-up/sign-in are wired functionally so the gate is reachable and demonstrable.
The full **"Account creation + sign-in" feature** (Phase 6) hardens copy, the
sign-up→bench transition (its memorable element), validation, and the
deliberate transaction-abort atomicity test. The atomic `bootstrap_tenant` shape
lives here from 5H so nothing has to be refactored later (wire-for-vision).
