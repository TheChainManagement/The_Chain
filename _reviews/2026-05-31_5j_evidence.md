## Fixes (`supabase/migrations/20260531140000_foundation_hardening.sql` + gate)

- **Claim integrity:** `custom_access_token_hook` only emits `tenant_id`/`role`/
  `token_generation` when a real `tenant_members` row exists. `profiles_update` /
  `profiles_insert` WITH CHECK require membership for `active_tenant_id`.
- **Partition side door (found while hardening):** `REVOKE ALL` on the
  `stock_movements_*` / `audit_log_*` partition children from `anon` +
  `authenticated` — direct child access bypassed the parent's RLS. Parent-routed
  queries unaffected (Postgres checks privileges on the parent).
- **Composite tenant FKs:** purchase_order_lines, supplier_performance,
  forecast_points, forecast_evaluations, cycle_count_lines, sync_conflicts,
  sync_runs, sync_failures re-keyed to `(tenant_id, parent_id)`.
- **PO recommendation:** `enforce_po_recommendation_tenant()` BEFORE trigger
  rejects a `recommendation_id` outside the row's tenant (the one user-mutable
  global ref; ON DELETE SET NULL precluded a composite FK).
- **Accepted:** `inventory_policy.based_on_forecast_id` (system-only mutate, no
  user write path).
- **Audit completeness:** `capture_audit` re-attached dynamically to every
  tenant_id table except `audit_log`.
- **App gate:** `getClaims()` reads the JWT `tenant_id`; membership is checked
  scoped to `(user_id, that tenant_id)`, so a stale token is bounced.
