## What can be done better

Decision question for MG: accept the skill substitution or require a formal Phase 3 re-run when the right orchestrator is available. This is the only process-level issue that can invalidate the gate. The evidence file was transparent (`projects/the-chain/_reviews/2026-05-30_design_evidence.md:23`), and PROCESS allows explicitly stated skipped steps with reasons (`PROCESS.md:254`-`PROCESS.md:281`), but Phase 3 is explicit that build-beautiful runs and its phases must actually execute (`PROCESS.md:113`-`PROCESS.md:140`). If MG accepts the substitution, record it as an exception. If not, re-run Phase 3 with the actual skill when available.

Decision question for MG: decide whether The Chain should be a disciplined cobalt-accent system or a cobalt-forward brand system. The design doc promises cobalt is capped at three visible uses (`projects/the-chain/DESIGN_DIRECTION.md:80`-`projects/the-chain/DESIGN_DIRECTION.md:81`), but the HTML uses cobalt everywhere listed above. This is fixable by demoting logo glyph, headline accents, done states, right-rail dots, and confidence bars to deep slate / semantic colors / hairline variants. It needs an MG decision only because the current sample may look more "alive" precisely because it violates the cap.

Fix: add the dotted lattice or remove the claim. Right now the direction says atmosphere over solid colors, but the sample is overwhelmingly solid surfaces and borders. The easiest fix is a reusable `.empty-lattice` / `.panel-empty` background using the declared hairline color and opacity, then place it in one empty/right-rail zone. If the product will rarely show empty zones in hero samples, remove the lattice as a flagship proof point. The current mismatch is not acceptable because evidence claims it as applied (`projects/the-chain/DESIGN_DIRECTION.md:160`-`projects/the-chain/DESIGN_DIRECTION.md:164`; `projects/the-chain/_reviews/2026-05-30_design_evidence.md:20`).

Fix: either implement shimmer or uncheck it. The motion floor is already satisfied by pulse, signal scan, and scroll progress (`projects/the-chain/samples/hero.html:86`-`projects/the-chain/samples/hero.html:109`, `projects/the-chain/samples/hero.html:223`-`projects/the-chain/samples/hero.html:233`), so shimmer is not required for the sample. But `[x] Shimmer` in DESIGN_DIRECTION is false as implemented (`projects/the-chain/DESIGN_DIRECTION.md:133`-`projects/the-chain/DESIGN_DIRECTION.md:138`).

Fix: stop using linear easing where PROCESS says spring easing only. PROCESS motion floor says spring easing only and `transform` + `opacity` only by default (`PROCESS.md:9`-`PROCESS.md:13`). The scroll progress bar uses `transition: width 80ms linear` and JavaScript mutates `bar.style.width` (`projects/the-chain/samples/hero.html:102`-`projects/the-chain/samples/hero.html:109`, `projects/the-chain/samples/hero.html:678`-`projects/the-chain/samples/hero.html:690`). Scroll progress width is a defensible exception because progress bars naturally encode width, but the exception is not documented in a top-of-file comment as PROCESS requires for motion deviations (`PROCESS.md:9`-`PROCESS.md:13`). Document the exception or change the implementation.

Fix: the letter spacing violates the current frontend guidance even if it is subtle. The sample sets `body { letter-spacing: -0.005em; }` and the headline uses `letter-spacing: -0.025em` (`projects/the-chain/samples/hero.html:75`-`projects/the-chain/samples/hero.html:84`, `projects/the-chain/samples/hero.html:235`-`projects/the-chain/samples/hero.html:245`). The current frontend design instruction says letter spacing must be 0, not negative. This is outside PROCESS.md, but it is still an active build instruction in this environment. Fix before production components inherit it.

The Working Bench is mostly not a 3-column card grid in disguise, but it is flirting with generic SaaS because the hero surface is a product-dashboard screenshot masquerading as a whole page. The layout is rails + main + rail (`projects/the-chain/samples/hero.html:165`-`projects/the-chain/samples/hero.html:179`), not three equal cards. But the right rail is literally `.right-card` repeated (`projects/the-chain/samples/hero.html:436`-`projects/the-chain/samples/hero.html:442`, `projects/the-chain/samples/hero.html:645`-`projects/the-chain/samples/hero.html:662`), the metric strip is a three-column stat row (`projects/the-chain/samples/hero.html:395`-`projects/the-chain/samples/hero.html:424`, `projects/the-chain/samples/hero.html:625`-`projects/the-chain/samples/hero.html:641`), and the chain links read as five flat cards (`projects/the-chain/samples/hero.html:327`-`projects/the-chain/samples/hero.html:350`). This does not fail anti-convergence, but production needs stronger "bench" behavior: more table/grid density, real selected-row mechanics, and fewer isolated panels posing as cards.

Distinctive typography is acceptable but not bulletproof. Mona Sans + IBM Plex is a credible operator-tool stack and diverges from prior projects (`projects/the-chain/DESIGN_DIRECTION.md:36`-`projects/the-chain/DESIGN_DIRECTION.md:42`). The risk is that IBM Plex Sans + Plex Mono can still pass for a conservative enterprise SaaS template if Mona Sans variable-width behavior is not used visibly. The sample sets `font-variation-settings: "wdth" 100` on the logo, headline, and right-card heading (`projects/the-chain/samples/hero.html:121`-`projects/the-chain/samples/hero.html:126`, `projects/the-chain/samples/hero.html:235`-`projects/the-chain/samples/hero.html:245`, `projects/the-chain/samples/hero.html:455`-`projects/the-chain/samples/hero.html:460`), which is effectively the default width. Accessibility fix: secondary/tertiary label contrast is weak in places. Cobalt on white passes, but `--color-dim: #8A95A3` on white calculates around 3.04:1, below 4.5:1 for normal text. That color is used for rail labels, link steps, pending text, right-card labels, and footer labels (`projects/the-chain/samples/hero.html:182`-`projects/the-chain/samples/hero.html:189`, `projects/the-chain/samples/hero.html:359`-`projects/the-chain/samples/hero.html:393`, `projects/the-chain/samples/hero.html:443`-`projects/the-chain/samples/hero.html:454`, `projects/the-chain/samples/hero.html:490`-`projects/the-chain/samples/hero.html:494`). Accessibility fix: cobalt hover/bright states on dark/dim backgrounds are not the main problem, but the system has no dark-surface rule. `#1B5BD9` on `#11161C` calculates around 3.07:1, which fails normal text but can pass for non-text UI indicators if large enough. The design declares dark/deep slate and signal-bright colors (`projects/the-chain/DESIGN_DIRECTION.md:59`-`projects/the-chain/DESIGN_DIRECTION.md:67`), but the sample mostly uses cobalt on light surfaces. Before the app gets dark/inset hover states, define contrast-safe text and indicator pairings instead of assuming cobalt works everywhere.

The headline word stagger at 60ms is acceptable but derivative. The sample delays word animation by 60ms steps for most words, with one 120ms pause before "Reorders" (`projects/the-chain/samples/hero.html:251`-`projects/the-chain/samples/hero.html:258`). More Technologies editorial broadsheet already uses 60ms word reveal as a signature motion (`projects/more-technologies-site/DESIGN_DIRECTION.md:93`-`projects/more-technologies-site/DESIGN_DIRECTION.md:117`). This is not an anti-convergence axis failure because motion is not one of the three hard axes, but it is a taste convergence. If The Chain wants an operator identity, consider row/chain-state reveal instead of editorial word reveal.
