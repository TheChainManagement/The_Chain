## What can be done better

- The movement summary lies on retries and duplicates. [`applyMovementDeltas()`](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/qbo/incremental-core.ts:321) uses `upsert(... ignoreDuplicates: true)` at [`352-355`](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/qbo/incremental-core.ts:352) and then blindly increments `summary.movements` by `staged.length` at [`357`](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/qbo/incremental-core.ts:357). That reports attempted rows, not inserted rows. On any replay-safe rerun, the operator gets fake “new movement” counts.
- Movement failures are still being silently dropped. Unknown products and unreadable dates hit `continue` at [`333-336`](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/qbo/incremental-core.ts:333), but `recordErrors()` only persists adapter-level `PullResultError`s at [`484-500`](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/qbo/incremental-core.ts:484). That is the exact class of silent loss this project has already been burned by elsewhere.
- The supplier delta path knowingly reintroduces duplicate-risk instead of converging with the initial-sync resolution logic. The comment at [`271-273`](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/qbo/incremental-core.ts:271) says identity is case-insensitive name, then immediately ignores that and inserts by QBO id anyway at [`274-282`](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/qbo/incremental-core.ts:274). That is not a contract-quality merge strategy; it is a shortcut with data-shape consequences.
- The current “needs review” dedupe is too blunt. Pending conflicts are deduped only by `entity_id` loaded into a `Set` at [`405-415`](/Users/themoreapp/More%20Technologies/projects/the-chain/src/lib/qbo/incremental-core.ts:405). A newer remote state for the same entity while an old pending conflict exists gets suppressed entirely. You avoided spam, but you also threw away state progression.

## What was missed

This slice did append-only movement writes, which is good, but it never pressure-tested the actual edge cases that matter: duplicate external receipts with corrected quantities, same `source_ref` with changed timestamps, and reconciliation behavior when QBO revises a bill after first sync.
